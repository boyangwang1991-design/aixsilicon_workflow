建议将分类主线定为：**CBB 面向逻辑复用与 PPA 优化，IP 面向 SoC 集成与系统功能交付。** 不以代码量或模块大小作为主要判据。

按照你的定位，可以采用下面这套分类原则。

**1. CBB：可复用的基础逻辑组件**

CBB 用于构建 IP，提供边界清晰、可重复使用的核心逻辑能力，重点关注逻辑正确性、参数化能力和 PPA。

* **核心逻辑为主**：通常不包含软件可见的寄存器体系、驱动接口及完整的系统管理功能。
* **接口简单**：主要采用信号级接口、握手接口或简单数据通路接口，一般不承担完整 APB/AXI 等协议的事务处理。
* **具备复用价值**：适合在多个 IP 或多个设计场景中使用，而非仅为某个 IP 拆出的内部子模块。
* **与 PPA 强相关**：适合集中优化关键路径、面积、功耗、扇出、流水级数及存储实现，并让多个 IP 共享优化成果。
* **以逻辑能力交付**：参数、端口、时序行为和使用约束构成主要契约。

典型 CBB：FIFO、仲裁器、优先编码器、计数器、CRC、ECC 编解码、同步器、握手 CDC、流水切片、锁步比较器。

**2. IP：面向集成的功能组件**

IP 是 SoC 或子系统集成时选用的功能单元，具有完整的功能边界、接口契约及集成要求。

* **具备独立的集成功能**：在 SoC 架构或集成清单中有明确用途，可以作为整体配置、连接和验证。
* **负责系统接口适配**：按需实现 APB、AXI、AHB、AXI-Stream、外设接口或专用接口。
* **提供完整功能闭环**：按功能需要包含控制、数据处理、状态、异常处理、中断、DFX 等能力。
* **以集成能力交付**：明确时钟复位、地址空间、接口协议、配置参数、性能及集成约束。
* **可以组合多个 CBB**：由 CBB 提供基础逻辑，IP 负责组织这些逻辑并承担整体功能责任。

典型 IP：GPIO、SPI Controller、Watchdog、DMA、AXI→APB Bridge、APB DEMUX、AXI MPU、SRAM Controller、Scheduler。

**IP 不要求一定具有 APB/AXI 接口，也不要求一定具有寄存器或驱动。** 是否形成独立的集成功能，才是主要依据。

**3. 分类判定表**

| 判定维度  | CBB           | IP                |
| ----- | ------------- | ----------------- |
| 主要使用者 | IP 设计者        | SoC／子系统集成者        |
| 复用对象  | 核心逻辑与微架构实现    | 完整功能组件            |
| 功能边界  | 一项基础逻辑能力      | 一项独立集成功能          |
| 接口特点  | 信号、握手、简单数据通路  | 标准协议或完整专用接口       |
| 软件可见性 | 通常不可见         | 按需提供寄存器、描述符、中断    |
| 优化重点  | 逻辑级 PPA、实现结构  | 系统功能、吞吐、延迟及整体 PPA |
| 交付重点  | 参数、端口、时序、使用约束 | 功能、协议、配置、异常与集成约束  |

**4. 边界模块按“承担的责任”分类**

**包含 AXI/APB 信号，不直接决定它就是 IP；与 PPA 强相关，也不直接决定它就是 CBB。**

| 模块                           | 建议分类 | 理由                       |
| ---------------------------- | ---- | ------------------------ |
| 通用 ready/valid 流水切片          | CBB  | 提供局部时序切分和数据保持能力          |
| AXI 通道打拍逻辑                   | CBB  | 若仅承担通道级缓冲与时序优化，仍属于基础逻辑   |
| 完整 AXI Register Slice／TPI 组件 | IP   | 若作为独立集成组件交付，负责完整接口及通道间约束 |
| 地址匹配、权限比较逻辑                  | CBB  | 只产生匹配结果或授权结果             |
| AXI MPU／安全 APB DEMUX         | IP   | 负责访问拦截、协议响应、权限配置及异常上报    |
| ECC Encoder／Decoder          | CBB  | 提供编码、纠错及错误检测核心逻辑         |
| 带 ECC 的 SRAM Controller      | IP   | 负责存储访问、仲裁、读改写及错误管理       |
| 仲裁器                          | CBB  | 提供请求选择与公平性逻辑             |
| Scheduler                    | IP   | 负责任务入队、依赖管理、派发及完成处理      |
| 锁步比较器                        | CBB  | 提供信号对齐、屏蔽、比较及局部故障指示      |
| 锁步管理控制器                      | IP   | 负责主影核协同、复位控制、诊断及系统故障管理   |

这里可以采用**“CBB 核心＋IP 封装”**：核心逻辑只维护一份，IP 增加必要的协议适配与集成功能。无需为了分类而强制增加一层空封装。

**5. 仓库管理补充规则**

* **普通内部模块不必独立入库。** 仅服务于单个 IP、缺少独立复用价值的模块，保留在该 IP 内部。
* **Parameterized／Generator 是实现方式，独立于 CBB／IP 分类。** ECC Generator 可以属于 CBB，SRAM Controller Generator 可以属于 IP。
* **分类以主要交付形态为准。** 不因某个 CBB 在顶层被直接实例化，就自动升级为 IP。
* **CBB 应有可验证的 PPA 特性或实现约束。** 不要求每个 CBB 都存在多套优化版本，但应明确关键路径、组合／流水实现、延迟和资源随参数变化的关系。

可直接写入规范的定义：

> **CBB 是面向 IP 开发的可复用基础逻辑组件，以核心逻辑能力为边界，通常采用简单接口，不承担完整的系统级协议与软件管理功能，重点实现参数化复用及逻辑级 PPA 优化。**
>
> **IP 是面向 SoC 或子系统集成的功能组件，以独立集成功能为边界，提供完整的接口契约、功能行为及集成约束，可由多个 CBB 和专用逻辑构成。**
